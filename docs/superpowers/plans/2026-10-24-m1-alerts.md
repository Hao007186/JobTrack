# M1 觸發規則與通知 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 查到價格後套用觸發規則產生 alert、站內通知中心與 API、用 DB 寄件匣搭配 SMTP 寄出 Email，並補上系統通知、編輯後重置通知狀態與示範通知。

**Architecture：** 新增 `modules/alerts`（`rules.py` 是不碰 DB 的純規則；`service.py` 把規則套到 DB）與 `modules/notifications`（通知與設定的 models、通知文字、系統通知、寄信器、notifier、API）。checker 在寫入快照的同一個 transaction 內寫入 alert、站內通知與 `pending` 的寄送紀錄；notifier 用 `FOR UPDATE SKIP LOCKED` 一次取一筆寄出。

**Tech Stack：** 既有的 FastAPI、SQLAlchemy 2.0 async、Alembic、pytest；寄信用標準函式庫 `smtplib`（不加新相依）。

**Spec：** [docs/superpowers/specs/2026-10-24-m1-alerts-design.md](../specs/2026-10-24-m1-alerts-design.md)

## Global Constraints
- 價格一律 TWD 整數；5% 門檻用整數運算 `price * 100 <= last_notified_price * 95`
- 原因與優先順序：`below_target` > `record_low` > `below_typical`；`alerts.reason` 存 `reasons[0]`
- 只對 `status = 'active'` 的追蹤套用規則；查不到航班（`result.lowest is None`）不判斷
- 系統通知只發站內通知，不建寄送紀錄；額度用完的 `dedupe_key` 為 `quota_exhausted:{YYYY-MM}`（台灣時間）
- notifier `MAX_ATTEMPTS = 5`；SMTP 逾時 30 秒、STARTTLS；錯誤訊息與 `last_error` 把 SMTP 密碼換成 `***`
- 設定預設：`EMAIL_SENDER=console`、`SMTP_PORT=587`、`APP_BASE_URL=http://localhost:5173`
- 測試不連網路、不寄真的信；SMTP 密碼（Resend API key）只放 `backend/.env`，不得寫進任何會進 Git 的檔案或指令列
- 對外的通知 id 一律用 `public_id`；別人的通知回 404；示範帳號寫入回 403（`WritableUser`）
- 新 model 加進 `app/db/models.py`；新指令加進 `tests/test_entrypoints.py`
- 指令在 `backend/` 下執行；ruff、mypy strict 通過；Commit 用 Conventional Commits、繁體中文，結尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- 寫檔用編輯工具，不用 bash heredoc

全套驗證指的是：`uv run pytest -q && uv run ruff check && uv run ruff format --check && uv run mypy`，全部通過。

## Review Focus
1. **價格剛好等於目標價、剛好等於典型區間下緣**：等於目標價算跌破（`<=`）；等於下緣不算低於（`<`） → Task 2 測試
2. **同一個 query 上兩位使用者、其中一位關閉 Email**：兩人都收到站內通知，只有開著的那位有寄送紀錄 → Task 3 測試
3. **寄送紀錄還在 pending 時使用者刪除追蹤**：寄送紀錄跟著刪除，notifier 不出錯；站內通知仍在，API 的 `booking_url` 為 null → Task 5、Task 6 測試
4. **快照沒有訂票連結（mock）**：信件省略「訂票：」那一行，不印出 `None` → Task 5 測試
5. **翻頁時多則通知的 `created_at` 相同**：用 `(created_at, id)` 一起比較，不漏也不重複 → Task 6 測試
