# M1 追蹤功能 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 實作機場／航空公司參考資料、追蹤的新增／查詢／編輯／暫停／恢復／刪除、全站 8 個與每人 3 個的名額規則、立刻補位與每日過期維護，並加入示範追蹤。

**Architecture：** 新增 `modules/reference`（唯讀參考資料）與 `modules/watches`。`watches/slots.py` 集中名額規則（全站 advisory lock、query_hash、佔名額判斷、決定狀態、補位）；`watches/service.py` 是各操作的流程，每個寫入操作「拿鎖 → 改資料 → 補位 → 單一 commit」；router 只轉換 HTTP。「今天」一律由呼叫端傳入，API 透過 `get_today` dependency 取得，測試可覆寫。

**Tech Stack：** 既有的 FastAPI、SQLAlchemy 2.0 async、Alembic、pytest；Postgres `ARRAY`、`pg_advisory_xact_lock`、`INSERT ... ON CONFLICT`。

**Spec：** [docs/superpowers/specs/2026-10-23-m1-watches-design.md](../specs/2026-10-23-m1-watches-design.md)

## Global Constraints
- 「今天」= 台灣時間（UTC+8，台灣沒有夏令時間，用固定時差 `timezone(timedelta(hours=8))`，不需要 tzdata）
- 出發日：`today + 3` ～ `today + 330`（含兩端）；回程不早於出發、≤ `today + 330`
- `MAX_ACTIVE_QUERIES = 8`、`MAX_WATCHES_PER_USER = 3`（只算 `active` + `queued`）、`STOP_CHECK_DAYS = 2`
- 佔名額：query 至少 1 個 `active` 追蹤、`is_demo = false`、`depart_date > today + 2`
- `cabin` ∈ `economy`／`premium_economy`／`business`／`first`；`adults` 1～9；`target_price` 1～1,000,000；`status` ∈ `active`／`queued`／`paused`／`expired`
- IATA 代碼一律轉大寫後處理；`airlines` 去重並排序
- 錯誤訊息照抄：404「找不到追蹤」、409「每人最多 3 個追蹤」、409「已過期的追蹤不能修改」
- 每個寫入操作：開頭 `pg_advisory_xact_lock(WATCH_LOCK_KEY)`，結尾補位，整個操作只 `commit` 一次
- 新增、修改、刪除端點用 `WritableUser`；讀取用 `CurrentUser`；參考資料端點不需登入
- 測試的今天固定 `TODAY = date(2026, 11, 1)`
- 指令在 `backend/` 下執行；ruff、mypy strict 通過；Commit 用 Conventional Commits、繁體中文，結尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- 寫檔用編輯工具，不用 bash heredoc（中文內容在 heredoc 會出錯）

## Review Focus
1. **小寫的 IATA 代碼**（`"tpe"`、airlines `["ci", "BR", "CI"]`）：使用者預期照樣接受 → 轉大寫、去重、排序，和大寫輸入得到同一個 price_query → Task 4 測試
2. **只改部分欄位，但組合後不合法**（單程追蹤只送 `return_date` 早於既有出發日）→ 422 → Task 5 測試
3. **PATCH 送了和原本相同的條件值**（例如前端整份表單送回，出發日已經在 3 天內）：值沒變就不該觸發日期檢查、不該改狀態 → 200、狀態不變 → Task 5 測試
4. **同一個使用者建立兩個條件完全相同的追蹤**：允許，佔 2 個個人名額，但只佔 1 個全站名額 → Task 4 測試
5. **編輯被排隊的追蹤只改目標價**：排隊順序（created_at）不能變，仍是 `queued` → Task 5 測試
